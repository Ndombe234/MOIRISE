# MOIRISE — CROSS-MODULE MECHANISMS

## Purpose
These are canonical cross-module mechanisms. They are written once and referenced by modules.

## 1. Living Objects

### Purpose
A persistent evolving creation with lineage.

### Lifecycle
SEED → ACTIVE → VERSIONED → BRANCHED → MERGED/FORKED → CONVERTED/ARCHIVED.

### Allowed conversions
Idea→Story; Story→Game; Game→Challenge; Challenge→Event; Creation→Community proposal; Validated solution→World Memory candidate.

### Required fields
objectId; owner; creator attribution; seedRef; currentVersion; branches; contributorRefs; permissions; visibility; state; lineage; quality signals; share refs.

### Contribution
A contribution references prior version, operation, actor and timestamp. Attribution is retained across forks/merges.

### AI
May propose transforms/contributors/branches. It cannot silently merge, transfer ownership or expose private data.

## 2. Evolution Engine

### State model
Trace + Living World + Hidden Possibilities + Unexplored Paths + Evolving Identity + MORISE Double + Fun & Surprise.

### Loop
validated action → permitted signal → context → candidate → frequency/privacy policy → presentation → player reaction → learning signal.

### Suppression
No non-critical interruption while typing, playing, creating, reading or during a user-selected quiet state.

### Truthfulness
Every “return later” prompt references a real future state.

## 3. Fun & Surprise

Surprise classes:
contextual humor; rare event; mystery clue; coincidence; legendary moment; harmless visual surprise; mystery gift; memory callback.

Eligibility requires real trigger, cooldown and privacy checks.

## 4. MORISE DNA

Evidence is based on demonstrated actions/results.
Candidate dimensions: Exploration, Creation, Resolution, Strategy, Collection, Collaboration, Discovery, Experimentation.
Version the scoring rules.
No sensitive trait inference.

## 5. Convergence

### Detection
semantic, structural or behavioral compatibility across independent authorized trajectories.

### Guardrails
privacy filter; sensitive-feature exclusion; diversity; confidence threshold; anti-manipulation; rate limit.

### Output
ConvergenceCandidate or optional ConvergenceSpace.
Possible outcomes: branch, experiment, game prototype, challenge, event, community proposal, World Memory candidate.

## 6. Emergent Missions / Missions From Reality

Pattern of recurring unresolved problem → candidate mission → validation → solo or collective experiment → measured outcome → solution validation → World Memory candidate.

Mission cannot become an authoritative production rule without validation.

## 7. World Memory

### Candidate
claim + source refs + attribution + validation evidence + confidence + scope + retention + correction path.

### Retrieval
query → permission filter → evidence ranking → bounded context → provenance.

Private messages are excluded by default.

## 8. Moment Cards

Validated result → privacy projection → compact card → share token.
Moment never exposes private state.

## 9. Community formation by AI

Authorized affinity signals → candidate cluster → sensitive-feature exclusion → existing group lookup → confidence/diversity → abuse check → proposal → policy/consent → create/onboard.

## 10. Distributed compute

LOCAL/ON_DEVICE → TRUSTED_WORKER → COMMUNITY_WORKER → VERIFIED_PROVIDER.
Worker tasks require capability, resource profile, lease, sandbox and validator.

## 11. Translation

Source text remains canonical.
Cache by sourceHash+locale+policyVersion.
NoTranslate markers.
Local/browser-first when available.

## 12. Cross-module event rule
Producer owns mutation. Consumers react through events/projections.

## 13. No-new-navigation rule
Cross-module mechanisms never automatically create primary navigation entries.
